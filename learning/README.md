# Learning Path: From Zero to the Two Papers

If you want the shortest path with the least navigation, stop here and use `../LEARN_THE_PAPERS_ONE_FILE.md`.

This folder is the modular version of that same learning system.

This folder is a beginner-first learning track for understanding:

- the original ML-TCP benchmark paper in `references/`
- the newer realism-correction manuscript in `manuscript/`

If you do not want multi-file study, ignore the rest of this folder after opening `../LEARN_THE_PAPERS_ONE_FILE.md`.

It follows the Universal Learning OS loop:

1. Define the core.
2. Extract the rules.
3. Map the structure.
4. Study mistakes and edge cases.
5. Test recall.
6. Apply once.
7. Review with spacing.

## Audience

This track assumes you may know almost nothing about:

- continuous integration
- regression testing
- test case prioritization
- the source paper
- our paper

## Suggested 5-Session Path

### Session 1: Foundations

- Read `FOUNDATIONS.md`.
- Answer the quiz without looking back.
- Do the small application task.

### Session 2: Original Paper

- Read `ORIGINAL_PAPER_GUIDE.md`.
- Focus on what the original paper actually claims.
- Memorize the high-level result pattern before the exact numbers.

### Session 3: Our Paper

- Read `OUR_PAPER_GUIDE.md`.
- Focus on why our paper does not simply replace the old one.
- Learn the four realism gaps.

### Session 4: Comparison

- Work through `SYNTHESIS_WORKBOOK.md`.
- Practice saying how the two papers differ in one minute.
- Write the decision memo task.

### Session 5: Teach-Back

- Explain both papers out loud without notes.
- Re-answer the hardest quiz questions.
- Redo one application task from memory.

## Hard Learning Rules

- Three-pass cutoff: do not reread forever. After three passes, produce output.
- One note format: topic -> principles -> mistakes -> application.
- One flashcard format: question -> reasoning -> answer.
- One review cadence: 1, 3, 7, 14, 30 days.
- Apply within 24 hours once you can explain or predict the idea.

## What “Success” Looks Like

You are ready when you can do all four of these from memory:

1. Explain what TCP in CI is and why order matters.
2. Explain the original paper's main recommendation without reversing the failure-rate story.
3. Explain why our paper is about conditional validity rather than simple disagreement.
4. Give one realistic scenario where the original recommendation may weaken or fail.
