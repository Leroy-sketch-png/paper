# Paper Note: Revisiting Machine Learning based Test Case Prioritization for Continuous Integration

## Status

This note is based on the cleaned Markdown extraction in `2311.13413v1.md`.
Tables and exact numeric values are usable, but any figure-heavy claim should still be spot-checked against the PDF before citing it formally.

## What This Paper Tries To Answer

- How 11 machine-learning-based test case prioritization (TCP) techniques compare under one controlled setup for continuous integration (CI).
- Whether the metrics used in prior work are fair for cross-cycle comparison.
- Which techniques are effective, efficient, and actually applicable in CI.

## Experimental Setup

- 11 open-source GitHub projects.
- 800 recent commits collected per project.
- 11 ML-based TCP techniques compared.
  - 6 supervised-learning-based (SL).
  - 5 reinforcement-learning-based (RL).
- The paper argues that APFD, NAPFD, and especially NRPA are flawed for fair CI comparison.
- They introduce `rAPFD` (rectified APFD) for cross-cycle effectiveness comparison.
- They also evaluate training time, prediction time, and NTR (time reduction until the first failing test is found).

## Core Findings

### 1. The best technique depends on failure rate

- On more-failure subjects, ACER-PA performs best.
- On less-failure subjects, MART performs best.
- The paper attributes this split mainly to data imbalance.

Why this matters:
- There is no single globally best ML-TCP method.
- "Best model" claims are weak unless they are conditioned on the failure-rate regime.

### 2. Performance drift across CI cycles is mostly a training-data story

- The paper argues that performance changes across CI cycles are driven more by the amount of available training data than by code evolution or test churn.
- RL methods can improve later because they keep adapting online.
- SL methods can stagnate because they train once on early data and then freeze.

Strong result:
- Cross-subject pretraining materially helps.
- Pretrained MART reaches the optimal sequence on 80% of subjects.
- The original MART reaches the optimal sequence on 50% of subjects.

### 3. RL methods are typically much more expensive

- RL-based techniques generally need much longer training time than SL-based techniques.
- ACER-PA is effective but comparatively expensive.
- PPO1-LI is the clearest warning case on runtime cost.

### 4. Applicability is not guaranteed by effectiveness alone

- Most techniques fit within average commit intervals.
- PPO1-LI can still be impractical because prediction time can exceed just running the tests in some subjects.
- MART is the strongest practical option overall because it combines strong effectiveness with low overhead.

### 5. MART is the most robust practical recommendation

- MART is the best overall subject-level choice in the paper.
- It often saves more than 95% of the time to reveal the first failure.
- The paper still recommends ACER-PA for more-failure subjects and MART for less-failure subjects.

## Paper-Level Recommendations

- Use imbalance-aware techniques in CI.
- Try SMOTE or similar preprocessing when failures are rare.
- Use cross-subject data to pretrain and then finetune on the target project.
- Estimate test duration before applying TCP, because overhead can erase the value of prioritization.
- Do not rely on NRPA alone when comparing techniques across CI cycles.

## What Seems Most Important For Our Work

### A. Failure-rate stratification is mandatory

If we evaluate or build a TCP approach without separating low-failure and high-failure regimes, we risk drawing the wrong conclusion about which method is actually good.

### B. Transfer learning is one of the highest-leverage ideas in the paper

The pretraining result is not a minor detail. It is one of the strongest actionable outcomes in the study.

### C. Runtime cost has to be treated as a first-class metric

The paper is useful because it does not stop at ranking quality. It also checks whether the method is worth running in a CI loop.

### D. Metric choice can reverse conclusions

The paper explicitly argues that older comparisons were distorted by metric issues, especially around NRPA and cross-cycle comparability.

## Useful Numbers And Claims To Remember

- 11 projects.
- 11 compared ML-based TCP techniques.
- 800 commits per project.
- Pretrained MART: optimal on 80% of subjects.
- Original MART: optimal on 50% of subjects.
- MART can save more than 95% of time-to-first-failure in most subjects.
- PPO1-LI can be inapplicable in some subjects because prediction cost is too high.

## Cautions

- Some tables and figures are noisy in the Markdown extraction, so exact table values should be confirmed in the PDF if we cite them externally.
- The paper's recommendations depend on knowing whether a project is more-failure or less-failure, which itself requires early CI evidence.
- The study uses a specific feature pipeline and selected OSS projects, so the practical recommendation is strong but not universal.

## If We Use This Paper As A Baseline

1. Start from MART as the default practical baseline.
2. Add an imbalance-aware variant or SMOTE-style preprocessing.
3. Add a transfer-learning condition: cross-project pretrain plus project-specific finetune.
4. Track overhead explicitly, especially prediction latency.
5. Report results separately for low-failure and high-failure regimes.
6. Avoid any evaluation story that depends only on NRPA.
